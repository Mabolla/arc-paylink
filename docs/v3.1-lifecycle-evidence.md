## Feedback trace

V3.1 implements the request-management feedback captured in GitHub issue [#11](https://github.com/Mabolla/arc-paylink/issues/11): a creator-facing My Requests view, visible lifecycle status, safe cancellation, and a way to correct pending requests.

Direct editing is intentionally replaced by revoke-and-replace. This preserves the historical request and prevents a shared payment link from changing meaning after it has been sent.

## Verified lifecycle behavior

| Scenario | Verified result |
| --- | --- |
| Create | A managed pending request appears in My Requests. |
| Revoke pending | The original link remains readable as `revoked` and no payment action is offered. |
| Replace pending | A new request ID and a new obligation ID are created. |
| Old replaced link | The original link remains readable as `replaced` and points to its replacement. |
| Settlement | The server verifies an Arc receipt and the exact official-USDC transfer before recording `settled`. |
| Settled immutability | The payment link shows “This request is settled.” with no pay, revoke, or replace action. |
| Legacy compatibility | Existing V3 query-string payment links remain supported. |

## Security and storage properties

- Request history is append-only in private Vercel Blob storage.
- The creator management capability is stored server-side only as a hash.
- The plaintext capability stays in the creator's browser and is never placed in a payer URL.
- Only `pending` requests accept revoke or replace.
- Replacements never reuse the old request ID or obligation ID.
- Same-chain settlement requires a successful Arc receipt plus an exact official-USDC transfer match.
- Bridge settlement visibility requires the existing validated immutable correlation record.
- The payment path rechecks authoritative request status immediately before payment.
